- [x] 2.2 `LocationProvider`, `PlaceSearchService`, `MapView` 인터페이스를 정의하고, 브라우저 GPS 구현(`navigator.geolocation`)을 만든다. 완료 확인: 권한 허용, 거부, 시간 초과를 가짜 geolocation으로 흉내 낸 단위 테스트가 각각 올바른 결과(좌표/거부/실패)를 반환한다.
- [x] 2.3 카카오 `PlaceSearchService` 구현(주변 검색, 키워드 검색, 다음 페이지)을 만든다. 완료 확인: SDK 응답을 흉내 낸 테스트에서 위치 유무에 따른 호출 옵션(반경 1km, 거리순, 음식점 카테고리)과 결과 없음, 오류 처리가 검증된다.

## 3. 주변 식당 목록 (nearby-restaurants)

- [x] 3.1 화면 상태(위치, 목록, 로딩, 오류, 다음 페이지 여부)를 관리하는 훅/리듀서를 구현한다. 완료 확인: 가짜 어댑터로 허용, 거부, 조회 실패, 결과 없음, 서비스 오류, 더 보기의 상태 전환 테스트가 통과한다.
- [x] 3.2 목록 UI(이름, 카테고리, 거리), 로딩 표시, 안내 메시지(권한 거부, 결과 없음, 오류와 다시 시도), "더 보기" 버튼을 만든다. 완료 확인: 컴포넌트 테스트로 각 상태의 문구와 버튼이 나타나고, 실제 브라우저에서 위치를 허용하면 주변 식당이 거리순으로 표시된다.

## 4. 지도와 연동 (restaurant-map)

- [x] 4.1 `MapView`의 카카오맵 구현을 만든다. 현재 위치 마커, 식당 마커, 모든 마커가 보이도록 범위 맞춤, 목록 갱신 시 이전 마커 제거를 포함한다. 완료 확인: 실제 브라우저에서 마커가 표시되고 검색을 바꾸면 이전 마커가 사라진다.
- [x] 4.2 마커 선택과 목록 항목 선택을 연동한다(선택 상태 공유, 목록 강조, 지도 중심 이동). 완료 확인: 상태 테스트로 양방향 선택이 같은 식당을 가리키고, 브라우저에서 마커와 목록 클릭이 서로 반영된다.
- [x] 4.3 지도 표시 실패 처리: 지도 초기화만 실패하면 안내를 표시하되 목록/선택은 유지하고, SDK 로드 자체가 실패하면 지도 안내와 목록 오류 안내(다시 시도)를 함께 보여주며, 지도 다시 시도 버튼을 둔다. 완료 확인: 컴포넌트 테스트와, 실제 브라우저에서 (a) 지도 생성만 강제로 실패시킨 상태에서 안내가 보이고 목록이 동작하며 (b) SDK 요청을 차단한 상태에서 지도·목록 오류 안내가 함께 보이고 (c) 차단을 풀고 다시 시도하면 지도와 목록이 복구된다.

## 5. 키워드 검색 (restaurant-search)

- [x] 5.1 검색 입력창과 제출 동작을 구현한다. 빈/공백 입력은 요청하지 않고 안내하며, 위치가 있으면 반경 안에서, 없으면 위치 제한 없이 검색하고, 위치가 없을 때는 거리를 숨긴다. 완료 확인: 가짜 어댑터 테스트로 빈 입력 무요청, 위치 있음/없음 분기, 결과 없음 안내가 통과한다.
- [x] 5.2 검색 초기화 시 주변 식당 목록으로 돌아가게 한다. 완료 확인: 검색 후 초기화하면 이전 주변 목록과 지도 마커가 복원된다 (테스트 + 브라우저 확인).
